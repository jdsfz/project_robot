# 프로젝트 결정 기록

이 문서는 project_robot 팀의 합의사항과 미결정 안건을 기록하는 기준 문서입니다. 회의에서 결론이 나면 날짜와 근거를 함께 기록하고, 영향을 받는 요구명세서·아키텍처·인터페이스 문서도 갱신합니다.

## 현재 확정된 기준과 진행 사실

아래 내용은 현재 대화에서 확인된 프로젝트 기준 또는 상태입니다. 기술 설계의 세부사항까지 확정되었다는 뜻은 아닙니다.

| 항목 | 확인된 내용 | 비고 |
|---|---|---|
| 팀 규모 | 3명 | 사람별 담당은 미배정 |
| 업무 분할 | 세 파트로 나눔 | 담당 이름과 파트별 최종 책임 범위는 미정 |
| 개발 환경 | Ubuntu 24.04 / ROS 2 Jazzy / Gazebo Harmonic | 팀원 전원 설치 완료 |
| 보유 장비 | Raspbot V2, Raspberry Pi 5 버전 IoT 키트 | 구매·보유는 사용자 확인 |
| 실물 수동모드 | Raspberry Pi에 연결한 라즈봇 수동조작 가능 | examples/manual/manual_jiy.py는 수동모드 시험용 |
| Gazebo | 라즈봇 모델 및 구동 설정이 추가로 필요 | 아직 미구현 |
| 1차 시연 범위 | 미정 | 팀 미팅에서 결정 |
| 안전 정지 기준 | 미정 | 팀 미팅에서 결정 |

## 회의에서 결정할 안건

| ID | 안건 | 현재 상태 | 합의 후 갱신할 문서 |
|---|---|---|---|
| OPEN-01 | 세 파트의 사람별 담당자와 검토자 지정 | 미정 | 아키텍처·업무표 |
| OPEN-02 | 프로젝트 전체 기간과 단계별 목표일 | 미정 | 아키텍처·일정표 |
| OPEN-03 | 1차 시연 시나리오와 성공 조건 | 미정 | 요구명세서·아키텍처·시험표 |
| OPEN-04 | 이동 대상 추적, 자동 출동, 자동 충전의 1차 포함 여부 | 미정 | 요구명세서·아키텍처 |
| OPEN-05 | 안전 정지, 통신·센서 단절 시 동작, 실물 시험 제한 | 미정 | 요구명세서·인터페이스·시험표 |
| OPEN-06 | Raspberry Pi의 OS·ROS 배포판과 수동모드 실행 환경 | 미확인 | 장비 목록·환경 안내 |
| OPEN-07 | ROS 모듈 간 메시지·상태·오류·좌표·시각 계약 | 미정 | ROS 인터페이스 문서 |
| OPEN-08 | 요구사항별 시험 방법, 측정 기준과 완료 증거 | 미정 | 요구사항 추적·시험표 |

안건을 추가할 때는 OPEN ID를 이어서 사용합니다. 미팅 전에 알게 된 사실과 팀이 합의한 결정은 구분해 기록합니다.

## 갱신 규칙

- 회의 메모 원문은 docs/decisions/meetings/에 날짜를 포함한 파일명으로 보관합니다.
- 결정 기록에는 합의한 내용만 옮기고, 미결정 항목은 OPEN 안건에 남깁니다.
- 결정이 요구사항 범위나 완료 기준을 바꾸면 요구명세서를 함께 갱신합니다.
- 인터페이스 결정은 ROS 인터페이스 문서와 코드에 동일하게 반영합니다.
- README에는 현재 상태와 이 문서 링크만 간단히 유지합니다.
