# A 파트 요구사항 정의서 — 로봇 기반·주행

문서 버전 0.1 · 작성 2026-11-20 · 상태: 팀 검토용 초안

## 1. 목적과 범위

이 문서는 요구명세서 v0.1(산업안전_자율주행_요구명세서.docx)과 [시스템 아키텍처 및 개발 계획](../../architecture/시스템_아키텍처_및_개발_계획.md)에서 A 파트(로봇 기반·주행)에 해당하는 요구사항을 뽑아, 구현·시험이 가능한 단위로 다시 정리한 것입니다.

- **포함:** 실물 라즈봇 구동·센서 인터페이스, Gazebo 로봇 모델·구동, 수동 조작, 정지·명령 만료, (범위 확정 시) 위치 추정·지도·경로 계획·장애물 대응
- **제외:** PPE 인식·대상 추적(B 파트), 임무 상태·운영 화면·통합 흐름(C 파트)
- 요구명세서 원본 ID(ENV, MAN, NAV, OBS, NFR, SAF)와의 대응은 각 항목의 "원본 분류" 열에 표시합니다. 원본 문구와 다른 점이 있으면 원본이 우선합니다.

| Pi의 OS·ROS 배포판 | 미확인 | OPEN-06 |

| 정량 기준 (속도·정지거리·간격·오차) | 미정 — 아래 표의 "기준값"은 측정 후 합의 | OPEN-08 |

## 3. 요구사항 목록

**우선순위:** P1 = 1차 시연에 반드시 필요 / P2 = 1차 범위 확정 시 포함 / P3 = 후순위

**상태:** 미착수 · 진행 중 · 시험 대기 · 시뮬 통과 · 실물 통과 · 보류

### 3.1 환경·장비 (A-ENV)

| ID | 요구사항 | 원본 분류 | 우선 | 완료 기준 | 상태 |
|---|---|---|---|---|---|
| A-ENV-01 | Raspberry Pi의 OS·ROS 배포판, Raspbot_Lib 버전, Python 의존성을 기록한다. | ENV | P1 | 장비·환경 기록표가 저장소에 있음 | 미착수 |
| A-ENV-02 | 모터 보드·센서(초음파/적외선 등)·카메라의 연결 방식(I2C 주소, 장치 번호)을 기록한다. | ENV | P1 | 장비 연결도 작성 | 미착수 |
| A-ENV-03 | 차체 치수, 휠 반경·휠 간 거리(트레드·휠베이스), 센서·카메라 장착 위치를 실측 또는 제조사 자료로 확인한다. | ENV | P1 | 치수표 + 출처(실측/자료) 표기 | 미착수 |
| A-ENV-04 | Pi에서 ROS 2 Jazzy 노드를 실행할 수 있는지, 불가하면 대안(Docker, PC 측 브리지 등)을 정한다. | ENV | P1 | 결정 기록 등록 | 미착수 |

### 3.2 수동 조작·구동 (A-MAN)

| ID | 요구사항 | 원본 분류 | 우선 | 완료 기준 | 상태 |
|---|---|---|---|---|---|
| A-MAN-01 | 실물 라즈봇을 전진·후진·제자리 좌회전·제자리 우회전·정지로 수동 조작할 수 있다. | MAN | P1 | 동작별 시험 영상/로그 | 실물 동작 확인(시험 기록 미작성) |
| A-MAN-02 | 수동 조작 명령을 `/cmd_vel`(Twist)로 받아 실물 모터로 출력하는 ROS 2 노드를 제공한다. | MAN | P1 | `ros2 topic pub`으로 5개 동작 재현 | 미착수 |
| A-MAN-03 | 같은 `/cmd_vel` 명령으로 Gazebo 라즈봇 모델이 동일한 방향으로 움직인다. | MAN | P1 | 실물·시뮬 방향 대응표 | 미착수 |
| A-MAN-04 | 실물과 Gazebo의 출력부는 별도 어댑터로 분리하고, 입력 규약(토픽·단위·부호)은 공통으로 유지한다. | MAN | P1 | 설계 리뷰 + 어댑터 교체만으로 실행 전환 | 미착수 |
| A-MAN-05 | 메카넘 횡이동(linear.y)을 지원한다. | MAN | P2 | 좌·우 횡이동 시뮬/실물 시험 | 보류(범위 미정) |
| A-MAN-06 | 카메라 서보(좌우·상하)를 허용 각도 범위 안에서만 제어한다. | MAN | P2 | 범위 밖 명령 시 클램프 확인 | 실물 동작 확인(Flask) |

### 3.3 정지·안전 (A-SAF)

| ID | 요구사항 | 원본 분류 | 우선 | 완료 기준 | 상태 |
|---|---|---|---|---|---|
| A-SAF-01 | 명령이 일정 시간(현재 0.5초) 이상 끊기면 모터를 정지한다(명령 만료). | SAF, NFR | P1 | 명령 중단·네트워크 차단 시험에서 정지 확인, 정지까지 시간 기록 | Flask 버전만 구현 |
| A-SAF-02 | 정지 명령은 다른 모든 이동 명령보다 우선한다. | SAF | P1 | 이동 명령 중 정지 명령 시험 | 미착수 |
| A-SAF-03 | 노드 종료·예외 발생 시 모터를 정지 상태로 둔다. | SAF | P1 | Ctrl+C, 프로세스 kill 시험 | Flask 버전 atexit만 구현 |
| A-SAF-04 | 수동/자동 모드가 동시에 모터를 제어하지 않도록 명령 중재(모드 배타)를 둔다. | SAF | P2 | 두 소스 동시 송신 시 한쪽만 반영 | 미착수 |
| A-SAF-05 | 센서 데이터가 끊기면 자율 이동을 정지한다. | SAF, NFR | P2 | 센서 토픽 중단 시험 | 미착수 |
| A-SAF-06 | 소프트웨어와 독립된 하드웨어 정지 수단(전원 스위치 등)을 확인하고 시험 절차에 포함한다. | SAF | P1 | 팀 공동 검토 기록 | 미착수 |
| A-SAF-07 | 최대 속도 제한값을 설정 파일로 두고, 초과 명령은 제한한다. | SAF, NFR | P1 | 초과 명령 시험 | 미착수 |

### 3.4 주행·위치 추정 (A-NAV) — 1차 범위 확정 후

|---|---|---|---|---|---|
| A-NAV-01 | 바퀴 명령 또는 엔코더 기반 odometry와 `odom → base_link` TF를 발행한다. | NAV | P2 | TF 트리 확인, 직진 1 m 오차 기록 | 미착수 |
| A-NAV-02 | 시험 공간 지도를 만들고 `map` 좌표계로 위치를 추정한다. | NAV | P2 | 지도 파일 + 위치 오차 기록 | 미착수 |
| A-NAV-03 | 목표 위치(map 좌표)를 받아 경로를 계획하고 이동한다(Nav2 검토). | NAV | P2 | 목표 N회 도달률·오차 | 미착수 |
| A-NAV-04 | 목표 취소·만료 시 이동을 멈추고 결과를 보고한다. | NAV | P2 | 취소 시험 | 미착수 |
| A-NAV-05 | 주행 상태, 위치 유효성, 성공·실패·취소, 오류·정지 사유를 C 파트에 보고한다. | NAV | P1 | 인터페이스 합의 + 토픽 확인 | 미착수 |

### 3.5 장애물 대응 (A-OBS) — 1차 범위 확정 후

|---|---|---|---|---|---|
| A-OBS-01 | 전방 장애물이 기준 거리 안에 들어오면 감속·정지한다. | OBS | P2 | 거리별 정지 시험 | 미착수 |
| A-OBS-02 | 사람은 PPE 착용 상태와 관계없이 장애물로 취급해 회피·정지한다. | OBS, SAF | P2 | 사람 모형/실제 시험 | 미착수 |

| A-OBS-04 | 투명·반사 구조물 등 센서 미검증 영역은 지도상 금지구역으로 등록한다. | OBS | P3 | 금지구역 설정 확인 | 미착수 |

### 3.6 비기능 (A-NFR)
