## 1. 현재 구현 분석 (기준선)

### 1.1 examples/manual/manual_jiy.py

Raspberry Pi에서 실행하는 Flask 웹 서버입니다. ROS를 사용하지 않습니다.

| 구성 | 동작 |
|---|---|
| 입력 | 브라우저 버튼 → `POST /move` (FORWARD/BACKWARD/LEFT/RIGHT/STOP), `POST /camera` (LEFT/RIGHT/UP/DOWN/CENTER) |
| 바퀴 출력 | `car.Ctrl_Muto(모터번호, 값)` — 휠 4개 각각 부호 × 속도 |
| 속도 | 전후진 `SPEED=80`, 회전 `TURN_SPEED=60` (모터 파워 단위, m/s 아님) |
| 명령 만료 | `WATCHDOG_SEC=0.5` — 0.1초 주기로 검사, 0.5초간 명령 없으면 STOP |
| 서보 | `Ctrl_Servo` — pan 0~180°, tilt 0~110° 클램프, 10° 단위 |
| 영상 | OpenCV V4L2 640×480 MJPG → `/video` MJPEG 스트림 |
| 동시성 | `bus_lock`으로 바퀴·서보 I2C 명령 직렬화 |
| 종료 | `atexit`에서 정지 처리 |

휠 패턴 (FL, RL, FR, RR):

| 명령 | FL | RL | FR | RR |
|---|---|---|---|---|
| FORWARD | +1 | +1 | +1 | +1 |
| BACKWARD | −1 | −1 | −1 | −1 |
| LEFT (제자리) | −1 | −1 | +1 | +1 |
| RIGHT (제자리) | +1 | +1 | −1 | −1 |
| STOP | 0 | 0 | 0 | 0 |

모터 번호 매핑은 `MOTOR_ID = {FL:0, RL:1, FR:2, RR:3}`, 회전 방향 보정은 `DIRECTION`(현재 모두 +1)입니다.

**확인 필요:** 코드 주석은 속도 범위를 0~255로, simulation/examples/manual_sim.py 주석은 0~100으로 적고 있습니다. Raspbot_Lib의 `Ctrl_Muto` 실제 허용 범위를 확인해 설정값에 반영합니다.

### 1.2 기존 참고 자료

- simulation/examples/manual_sim.py: ros_gz_sim_demos의 diff-drive 데모 로봇(`/model/vehicle_blue/cmd_vel`)에 Twist를 보내는 예제. 라즈봇 모델이 아님.
- examples/robot_arch_example/: 입력 → 공통 바퀴 속도 → Pi/Gazebo 출력 선택 구조 예제. 아래 설계의 "어댑터 분리" 아이디어의 출발점.

## 2. 전체 구조

```
 [입력]                        [공통 제어]                       [출력 어댑터]
 웹 UI / 키보드 teleop ─┐
 C 파트 임무(목표)  ──→ Nav2 ─┼─→ /cmd_vel ─→ cmd_mux ─→ /cmd_vel_safe ─┬─→ raspbot_driver (Pi, Raspbot_Lib)
                              │                  ↑                       └─→ Gazebo (ros_gz_bridge → 메카넘 플러그인)
                              │          safety_monitor
                              │       (명령 만료·속도 제한·정지 우선)
 센서(초음파 등) ─────────────┴─→ /scan 또는 /range ─→ Nav2 costmap, safety_monitor
 odometry ──→ /odom, TF(odom→base_link) ──→ Nav2, C 파트 상태 보고
```

핵심 원칙:

1. **입력과 출력 분리** — 상위(teleop, Nav2)는 `/cmd_vel`만 알고, 실물인지 Gazebo인지 모릅니다.
2. **안전 계층은 출력 직전에 한 번** — 명령 만료·속도 제한·정지 우선을 `safety_monitor`/`cmd_mux` 한 곳에서 처리해, 실물·시뮬 모두 같은 규칙을 적용합니다.
3. **로봇 측 마지막 방어선** — 드라이버 노드 자체에도 명령 만료 타이머를 둡니다(네트워크·상위 노드가 죽어도 로봇이 멈추도록). 하드웨어 독립 정지는 별도로 확인합니다.

## 4. 토픽·좌표계

### 4.1 토픽 (굵게 표시한 것만 기존 인터페이스 문서에 있음)

| 토픽 | 타입 | 발행 → 구독 | 비고 |
|---|---|---|---|
| **/cmd_vel** | geometry_msgs/msg/Twist | teleop, Nav2 → cmd_mux | linear.x (m/s), angular.z (rad/s), linear.y는 횡이동 범위 확정 시 |
| /cmd_vel_safe | geometry_msgs/msg/Twist | cmd_mux/safety → driver, Gazebo | 제안 이름 |
| /odom | nav_msgs/msg/Odometry | driver 또는 Gazebo → Nav2, C | |
| /tf | tf2_msgs/msg/TFMessage | odom→base_link, base_link→센서 | |
| /range/front 등 | sensor_msgs/msg/Range | 센서 노드 → safety, Nav2 | 실제 센서 종류 확인 후 |
| /camera/image_raw | sensor_msgs/msg/Image | 카메라 노드 → B 파트 | B와 사용 방식 합의 필요 |
| /robot_status | 미정 (커스텀 메시지 검토) | A → C | 5장 참고 |

### 4.2 좌표계

`map → odom → base_link → {wheel_fl, wheel_rl, wheel_fr, wheel_rr, camera_link, range_front_link …}`

- 단위: 거리 m, 각도 rad, 시간 ROS time (REP-103 준수: x 전방, y 좌측, z 상방, 반시계 회전 +)
- Gazebo에서는 `use_sim_time:=true`

## 5. 파트 간 인터페이스 초안

### 5.1 C → A: 이동 목표

Nav2의 `nav2_msgs/action/NavigateToPose` 액션을 그대로 쓰는 방안을 1안으로 제안합니다(취소·피드백·결과가 이미 정의되어 있음). 임무 ID는 goal의 `behavior_tree` 필드가 아니라 별도 상태 토픽이나 래퍼 액션으로 전달하는 방법을 C와 정합니다.

| 정보 | 1안(Nav2 액션) | 합의 필요 |
|---|---|---|
| 목표 위치·방향 | `pose` (PoseStamped, frame_id=map) | — |
| 임무 ID | 미포함 | 래퍼 액션 또는 별도 토픽 |
| 취소 | 액션 cancel | — |
| 만료 | 미포함 | 만료 시각 전달 방법 |

### 5.2 A → C: 로봇 상태

| 필드 (제안) | 의미 |
|---|---|
| stamp | 상태 생성 시각 |
| mode | MANUAL / AUTO / STOPPED |
| nav_state | IDLE / MOVING / SUCCEEDED / FAILED / CANCELED |
| pose_valid | 위치 추정 유효 여부 |
| stop_reason | NONE / CMD_TIMEOUT / ESTOP / OBSTACLE / SENSOR_LOST / DRIVER_ERROR |
| mission_id | 현재 수행 중인 임무 ID (C가 준 값 그대로) |

메시지 타입(커스텀 msg vs diagnostic_msgs)과 발행 주기는 OPEN-07에서 결정합니다.

## 6. 구동 설계 — 메카넘 역기구학

`/cmd_vel_safe`의 (vx, vy, ωz)를 휠 각속도로 바꿉니다. 휠 반경 r, 좌우 휠 간 거리의 절반 Ly, 앞뒤 휠 간 거리의 절반 Lx, k = Lx + Ly일 때:

```
ω_FL = (vx − vy − k·ωz) / r
ω_FR = (vx + vy + k·ωz) / r
ω_RL = (vx + vy − k·ωz) / r
ω_RR = (vx − vy + k·ωz) / r
```

- vy = 0이면 기존 Flask의 5개 패턴과 같은 부호가 나옵니다(예: ωz > 0 좌회전 → 왼쪽 −, 오른쪽 +).
- 실물 출력: ω → 모터 파워 값 변환은 선형 근사 `power = clamp(ω × gain, −max, max)`로 시작하고, 실측(바닥에서 일정 파워로 1 m 이동 시간)으로 `gain`을 보정합니다.
- 휠 롤러 방향(X형/O형 배치)에 따라 vy 부호가 바뀔 수 있으므로 횡이동은 실물로 먼저 확인합니다.
- 파라미터(r, Lx, Ly, gain, max, MOTOR_ID, DIRECTION)는 `config/raspbot.yaml`에 둡니다(A-NFR-01).

### Gazebo 구동 방법

| 방안 | 장점 | 단점 |
|---|---|---|
| ① `gz-sim-mecanum-drive-system` 플러그인 | 공식 플러그인, Twist 직접 입력, 횡이동 지원 | 롤러 물리 대신 이상화된 모델 |
| ② `gz-sim-diff-drive-system` | 설정 간단, 1단계(전후진·회전) 충분 | 횡이동 불가 |
| ③ 휠 조인트 4개 개별 속도 제어 + 자체 역기구학 | 실물 드라이버와 같은 코드 경로 | 메카넘 롤러 마찰 재현이 어려움 |

**제안:** ①로 시작합니다. 횡이동 범위가 빠져도 그대로 쓸 수 있고, 나중에 필요하면 ③과 비교합니다.

## 7. 안전 정지 설계

| 계층 | 위치 | 동작 | 요구사항 |
|---|---|---|---|
| 1. 입력 측 | teleop UI | 버튼을 떼면 STOP 발행, 주기 송신(heartbeat) | A-SAF-01 |
| 2. 중재 | cmd_mux / safety_monitor | 정지 명령 최우선, 입력별 우선순위·만료(timeout), 속도 제한 | A-SAF-02·04·07 |
| 3. 드라이버 | raspbot_driver_node | 마지막 명령 후 0.5초(설정값) 지나면 모터 0, 종료·예외 시 모터 0 | A-SAF-01·03 |
| 4. 센서 | safety_monitor | 전방 거리 < 기준 → 정지, 센서 토픽 끊김 → 자율 이동 정지 | A-SAF-05, A-OBS-01 |
| 5. 하드웨어 | 로봇 전원 스위치 등 | 소프트웨어와 무관한 정지 | A-SAF-06 (팀 공동 검토) |

- 중재기는 ROS 패키지 `twist_mux` 사용을 우선 검토합니다(입력별 우선순위·timeout·lock 토픽 지원).
- 정지 후 **자동 재개 금지**: 정지 사유가 해소돼도 새 명령이 와야 다시 움직입니다.
- 0.5초, 최대 속도 등 수치는 기존 값을 임시로 쓰며, 안전 정지 기준(OPEN-05) 합의 후 확정합니다.

## 8. 설정 파일 예시 (초안)

```yaml
# raspbot_bringup/config/raspbot.yaml  (값은 실측 전 임시)
raspbot_driver_node:
  ros__parameters:
    wheel_radius: 0.0      # m, 실측 필요 (A-ENV-03)
    half_wheelbase: 0.0    # Lx, m
    half_track: 0.0        # Ly, m
    motor_id: {fl: 0, rl: 1, fr: 2, rr: 3}
    direction: {fl: 1, rl: 1, fr: 1, rr: 1}
    power_gain: 0.0        # rad/s → 모터 파워, 실측 보정
    max_power: 80          # Ctrl_Muto 허용 범위 확인 후 조정
    cmd_timeout_sec: 0.5
    max_linear_mps: 0.2
    max_angular_rps: 1.0
```

## 10. 미결정 사항과 위험

| 항목 | 영향 | 대응 |
|---|---|---|
| Pi에서 ROS 2 Jazzy 실행 가능 여부 (OPEN-06) | 드라이버 노드 위치 | Pi OS 확인 → 불가 시 Docker 또는 Pi는 Flask/소켓 유지 + PC 측 브리지 |
| 엔코더 유무 | odometry 정확도 | 없으면 명령 적분 odometry + 정확도 한계 명시 |
| 거리 센서 종류·개수 | 장애물 대응·Nav2 범위 | 장비 조사 후 A-OBS 범위 조정 |
| 횡이동 1차 포함 여부 | 인터페이스 linear.y | 1단계는 linear.x·angular.z만 |
| 카메라를 A·B가 공유 | 장치 점유 충돌 | 카메라 노드 하나가 발행, 나머지는 구독 |
